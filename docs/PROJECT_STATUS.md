## 現在の管理方針

- 直近の単発修正ではなく、データ取得、食品ダッシュボード、LP/SEO、管理画面を並列で進める。
- 各担当は編集範囲を分け、最後に主担当が統合、`npm.cmd run lint`、`npm.cmd run build`、ブラウザ確認を実施する。
- 公開データは商用利用条件と出典表記を分けて管理する。JNTOは「日本政府観光局（JNTO）」と明記する。
- 気象庁の時間別データは不要。日次、予報、長期予報、気温、降水量を中心に保存する。
- ローカルに10年分の元データ、Supabaseには公開画面用の直近1年とAI集計結果を保存する方針。

## 収益化仮説

- 無料: 一般向けの価格確認、買い時、都道府県別の簡易需要予測。
- 広告: スーパー、食品メーカー、仕入れ業者、民泊備品、業務用食材の地域広告。
- 有料ライト: 飲食店、民泊、個人店向けのアラート、代替食材提案、仕入れメモ。
- 有料プロ: スーパーのバイヤー、ホテル、チェーン飲食向けの地域別予測、CSV/API、過去比較。
- データ/API: 予測スコア、価格シグナル、観光消費シグナルのAPI提供。

## 残リスク

- 公的データごとに商用利用条件、出典表記、二次利用可否の確認が必要。
- スクレイピング対象はrobots.txt、利用規約、負荷対策を個別確認する。
- 日次データが存在しない統計は、月次/年次を短期換算していることを画面上で明記する。
- Supabase無料枠に収めるため、生データはローカル、Web側は集計済みデータ中心にする。
